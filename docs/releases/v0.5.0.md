# asca v0.5.0

Checks for how self-hosted agents get taken over in 2026: a rewritten persona, an open gateway, an exposed Docker API, a symlink left in the workspace and MCP servers nobody will patch. Plus a one-command check for repos a stranger asks you to open, and concrete steps when a key leaks. Same principles as always: Python standard library only, and asca never runs what it scans.

## What's new

### 🎭 Hermes persona and gateway tampering
The Carbonato botnet ([ThreatDown](https://www.threatdown.com/blog/carbonato/)) installs Hermes Agent unchanged, then overwrites `SOUL.md` with a "GH0ST" persona that takes tasks over Telegram, keeps itself installed and collects AI API keys and SSH credentials. The code and version don't change, so integrity checks see a clean install. asca's skill-content rules look for payloads and hidden text, and they found nothing in a persona like that, so persona files now get their own rules.
- **Files read:** `SOUL.md` and `memories/*.md`, including every profile under `profiles/*/`. They're read as text only.
- **Critical:** `persona.known-malware` (names `GH0ST`, ThreatDown's indicator) and `persona.c2` (several takeover instructions together). The second still fires when the persona is renamed.
- **High:** `persona.credential-harvest`, `persona.persistence` and `persona.conceal` (hide what it does from you). **Medium:** `persona.no-limits`. **Low:** `persona.remote-tasking`, which is normal for many setups and only counts toward `persona.c2`.
- **Instructions only:** the rules fire on text that tells the agent to do something. Text that describes an attack, and negated or prohibited lines ("never collect credentials"), don't count.
- **Open gateway:** `gateway.allow-all-users` (high) flags `GATEWAY_ALLOW_ALL_USERS=true` or a `*` in an allow list in a Hermes `.env`, which lets anyone who finds the bot command the agent. `gateway.known-malware-env` (critical) flags `CARBONATO_API_KEY` and `GH0ST_C2`. Only variable names and the access switches are read, never other values.
- **Changes are tracked:** `asca inventory` reports `inventory.persona-changed` and `inventory.access-changed` (medium) when `SOUL.md` or the list of who can command the agent changes. It stores only hashes, and the first run after upgrading learns them silently.
- **Skip it** with `--no-persona`.

### 🐳 Docker API exposed without client certificates
Carbonato gets in through Docker daemons that listen on TCP without authentication, and anyone who reaches such a port is root on the host. The new rule `host.docker-api-exposed` reads `daemon.json`, docker's systemd units and drop-ins, and `/etc/default/docker` or `/etc/sysconfig/docker`. It never contacts the daemon.
- **Critical:** listening on all interfaces. **High:** a specific network address (LAN, VPN, tailnet). **Medium:** loopback only.
- **Only `--tlsverify` counts as protection.** `--tls` alone encrypts the traffic but still lets anyone in.
- **Skip it** with `--no-docker-daemon`.

### 🔗 Symlinks that lead out of a repo or the agent home
In [CVE-2026-103916](https://www.endorlabs.com/learn/docker-sandboxes-vulnerability-lets-ai-agents-access-sensitive-files-outside-their-sandbox-cve-2026-103916) a sandboxed agent planted a symlink in its workspace, and a later copy followed it to host files. The new rule `repo.symlink-escape` lists links in every repo and the Hermes home with `os.readlink`. Targets are never opened or followed.
- **High:** the target is a credential location (`~/.ssh`, `~/.aws`, `.env`, `auth.json`, wallets, keychains, browser profiles) or a whole home folder.
- **Medium:** the link is committed and leaves the repo. **Low:** any other link that leaves the repo or the agent home.
- **Skipped:** links inside package-manager folders and virtualenvs, runtime socket folders, and Hermes cache folders.
- **Skip it** with `--no-symlinks`.

### 🪦 MCP servers that are archived and will never be patched
Anthropic archived 13 of its original reference MCP servers ([servers-archived](https://github.com/modelcontextprotocol/servers-archived)). [Glow Labs' MCPhantom research](https://www.glow.io/blogs/mcphantom-ai-coding-agents-are-installing-vulnerable-deprecated-mcp-servers-from-training-data) found coding agents still installing them from their training data. Before this release, pinning one made asca's "unpinned" finding go away, although no fixed version will ever exist.
- **New rule `mcp.archived-server`:** high for `server-puppeteer`, which has a prompt-injection-to-command-execution bug its maintainers declined to fix; medium for the other 12.
- **The list comes from the archive itself:** each server's `package.json` or `pyproject.toml`. `mcp-server-git` is excluded because it went back to the maintained repo.
- **The fix names the vendor's maintained server** where one exists: GitHub's `github-mcp-server`, Microsoft's `@playwright/mcp`, `@brave/brave-search-mcp-server`, Redis' `mcp-redis` and `@sentry/mcp-server`.
- **Add your own entries** with `--known-archived FILE`.

### 🧳 `asca check-repo PATH`: check a repo before you open it
Fake recruiters have sent developers "take-home tests" that run code the moment the repo is opened in an IDE or `npm install` runs. This new command checks one folder offline and prints one verdict.
- **⛔ Don't open it yet / ⚠️ Check these first / ✅ No red flags.** Add `--telegram always` to get the verdict on your phone, or `--json` for every finding.
- **Checks:** git config that runs programs, IDE and agent hooks that run on open, project MCP configs, saved allow rules, agent instruction files (against the skill-content rules), coding agents in `.github/workflows`, symlinks, and npm install scripts.
- **Install scripts are graded by what they run:** low for build tools such as `husky`, medium for a file from the repo, high when the script or the file it runs fetches, decodes or evaluates code.
- **Nothing in the repo is executed** and git is never run. A folder without `.git` (an unpacked zip) is treated as if every file were committed.

### 🚑 What to do when a key leaks
- **Provider steps:** every leaked-key finding (in config, transcripts, allow rules or MCP `env`) now says where and how to revoke that key. This covers Anthropic, OpenAI, OpenRouter, GitHub, Slack, Telegram's @BotFather, Google, Stripe and Hugging Face, plus private keys and wallets, which can't be revoked.
- **AWS blast-radius card:** each AWS key finding says which local profile the key is, whether it's long-lived or temporary, and which roles it can assume. It adds the `aws iam` commands to deactivate and replace it, and the CloudTrail lookup to see what it did. AWS isn't called, and neither the secret key nor the full key ID is written to a report.
- **Credentials file permissions:** `~/.aws/credentials` is now checked for group or world read access.

## Verified
- **Persona rules:** a persona written from ThreatDown's description is rated critical, and still critical with the `GH0ST` name removed. A real Hermes `SOUL.md` and its memories give 0 findings, and so do 548 other real Markdown files (Hermes skills, project docs, research notes).
- **Install scripts:** across the root `package.json` of 39 popular JS projects (React, Next.js, VS Code, Vite, Angular, Electron …), nothing is rated high. The 13 medium findings each run a file from the repo.
- **`check-repo`:** 18 real repos come out ✅. A fake malicious take-home repo comes out ⛔, and nothing in it ran.
- **Symlinks:** of 472 real links across 18 repos and a Hermes home, 2 leave their folder, both low and both genuine.
- **On a real Hermes host:** the daily audit stays PASS with one new low finding, and the first inventory run learns the new items without alerting.

## Upgrade notes
- **New findings may appear in the daily audit:** persona, gateway, Docker and symlink checks are on by default. Only high and critical findings fail the audit, so `--telegram change` alerts once if one appears.
- **No alert from the inventory upgrade:** `SOUL.md` and the access settings are learned on the first run. Later changes are reported.
- **Archived MCP servers:** a server you pinned to stop the "unpinned" finding is reported again if it's on the archived list. That's intended.
- **The new `asca check-repo` command** has its own options; see the README.

## Limits
- **Persona rules read English instructions.** A rewritten persona in another language, or one that changes the agent's goals without these phrases, is caught by the inventory's `SOUL.md` hash, not by content.
- **The symlink check** finds links left on disk or committed. A link created and used within one run is gone before asca looks.
- **The Docker check** reads the host's daemon configuration. Run inside a container, it can't see the host's.
- **`check-repo`** reads what's in the folder. It doesn't follow dependencies or run code, so the safest way to try an untrusted repo is still a throwaway VM or container with no keys in it.
