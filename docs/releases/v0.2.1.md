# asca v0.2.1

A security update for one specific leak: coding agents saving your secrets in their allow lists. When you approve a command with **"Yes, and don't ask again"**, Claude Code stores the *literal* command (password included) in `.claude/settings.local.json`. That file is excluded only in your global git config, so it's easy to commit. Apiiro found 104,185 public copies on GitHub, 1,122 of them with a real secret, and 215 that neither gitleaks nor TruffleHog flagged ([research, 5 Nov 2026](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again)). asca 0.2.0 checked allow rules for dangerous settings but didn't secret-scan them. 0.2.1 does.

## What's new

### 🔐 Secrets in agent allow lists (on by default)
- **What it scans:** every Claude Code `allow` / `ask` / `deny` rule, in `~/.claude` settings, managed settings, every repo's `.claude/settings*.json` and older Claude Code's `allowedTools` in `~/.claude.json`.
- **VS Code agent auto-approve settings:** in VS Code, Insiders, Cursor, Windsurf and VSCodium user settings and in every repo's `.vscode/settings.json`. The keys are `chat.tools.terminal.autoApprove` and `chat.tools.urls.autoApprove`, plus the older `chat.agent.terminal.allowList`.
- **Severity:** provider keys and passwords for public hosts are high; passwords for local or private hosts are medium. Findings show the rule with the secret redacted.

### 🗂️ Committed or unprotected `settings.local.json`
- **Committed to git:** high if it holds a secret, medium otherwise. This is read from `.git/index`; git is never run.
- **Not excluded by the repo's own `.gitignore`:** low, with the one-line fix (`echo '.claude/settings.local.json' >> .gitignore`). Global excludes don't count, because they protect only your machine.
- **Committed `.specstory/` agent transcripts:** medium, and their contents are secret-scanned.
- **Fix steps, in order:** rotate first (removal doesn't clear history, forks or clones), then `git rm --cached` and the repo's `.gitignore`, delete the rule, use `$VAR` in commands, and approve patterns like `Bash(npm run:*)`.

### ⌨️ Passwords typed into commands (every secret scan)
- **What it detects:** `PGPASSWORD=`, `MYSQL_PWD=`, `REDISCLI_AUTH=`, `SSHPASS=`, `mysql -p…`, `--password=`, `sshpass -p`, `user:pass@host` URLs (postgres, mysql, mongodb, redis, amqp, http(s), ftp, smtp, ldap), `curl -u user:pass` and `Authorization: Bearer …` (JWTs included).
- **Where it applies:** allow rules, `.env` and config files, MCP server definitions and agent session history.
- **Severity follows the host:** public hosts are high (`secret.command-password`); loopback, private ranges, `*.local`, compose service names and documentation hosts are low (`secret.command-password-private`).
- **Not flagged:** variables (`$PGPASSWORD`, `${DB_PASS}`), placeholders (`<password>`, `***`), common example passwords and URLs without a host.
- **False positives:** 0 hits on a benchmark of 15,685 benign files (5.2 million lines: official Hermes skills, community skills, real repos and a full Python `site-packages`).

### 🍎 One-command check
`docs/macos.md` section 4b has a single command that checks your Claude Code and VS Code allow lists, every repo under `~/Projects` and your agent session history.

## Upgrade notes
- **Expect one alert after upgrading.** The command-password detector also runs on agent session history, so passwords and bearer tokens in old transcripts will show up once (`secret.session-history`). Rotate anything live, then accept revoked ones in your baseline with `--write-baseline` (and edit the file).
- **Session-history severities:** the new command-password findings are high for public hosts and low for local or private hosts. Existing rules keep their severities.
- **New flag:** `--no-agent-allowlist` turns the new allow-list and `settings.local.json` checks off.
- **Limits:** only the Claude Code and VS Code stores above are read (not Codex rules, Cursor's own allow list or aider transcripts). A password and its host on different lines aren't connected. The `.gitignore` check covers the common subset of git's rules.

**Tests:** 374 passing.
