# asca v0.3.0

Three new checks, each from published research from the last month and each found by asca's own weekly research job. Same principles as always: Python standard library only, and asca never runs what it scans.

## What's new

### 🧬 Bytecode that runs instead of the source (PyCache Trap)
A skill can ship harmless `helper.py` next to a `__pycache__/helper.cpython-313.pyc` whose code is different. Python's loader accepts a cache whose header matches the source, then runs the *cache*, so what you reviewed isn't what executes. In the PyCache Trap study this got past seven skill scanners in 94–100% of cases ([arXiv 2610.10612](https://arxiv.org/abs/2610.10612)).
- **How it works:** asca reads every `.pyc` header in each skill and works out what CPython would do with it. Only for caches Python would actually load, it compiles the visible source and compares the code objects, in a separate `python -I -S` helper process. Nothing in the cache or the source is executed.
- **`skill.bytecode-mismatch` (high):** a cache Python accepts (header matches the source, or an unchecked hash-based cache) whose code differs from the source.
- **`skill.bytecode-sourceless` (high):** a `.pyc` with no `.py` beside it, which `import` runs directly.
- **`skill.bundled-bytecode` (low/medium):** orphan, malformed or foreign-version caches.
- **No noise from normal use:** caches Python wrote itself match their source and stay quiet. Stale caches are ignored, because Python recompiles them.

### 🚦 Skills that tell the agent to skip its own checks
About 1 in 17 skills contain an *oversight-loosening* directive, and open-source scanners catch at most 46% of them ([arXiv 2610.37734](https://arxiv.org/abs/2610.37734)).
- **New rule `skill.inject.oversight-loosening`:** `--no-verify`, `--no-gpg-sign`, `HUSKY=0`, "proceed without approval", "don't check in", "don't ask before pushing", "skip code review / hooks / verification".
- **Severity:** medium by default; high for a concrete flag or a script in a skill that also runs shell, `sudo` or package installs; low when scoped to CI/automation or in a documentation table.
- **Ignored:** tightening ("never use `--no-verify`", "never ask the user for their password", items under a "Never do these" heading) and UX guidance about clarifying questions.

### 🪝 Gemini CLI hooks in cloned repos
Gemini CLI runs hook commands from a project's `.gemini/settings.json`, and project settings override the user's ([docs](https://geminicli.com/docs/hooks/)). JFrog lists the file among the AI/IDE hook files in 42 GitHub repos hijacked by the testmetest campaign ([JFrog, Oct 2026](https://research.jfrog.com/post/beyond-testmetest-42-hijacked-github-repos/)).
- **Repo hook check:** now reads `.gemini/settings.json` with the same rules as Claude Code, Cursor and VS Code (committed vs local, high for commands that fetch or send data).
- **MCP servers:** the file's `mcpServers` are audited like a repo's `.mcp.json`.

### 🖼️ Social preview card
`docs/assets/` holds the repository's link-preview image and its HTML source, with re-render steps.

## Verified
- **False positives:** 186 official Hermes skills (Hermes 0.23.0), scored as if their origin were unknown, give **0 high or critical** findings. The new rule adds 2 medium and 3 low across all of them.
- **On a real Hermes host:** the daily skill scan and audit results are unchanged by the new rules.
- **Recall:** forged PyCache Trap caches (timestamp and unchecked-hash variants) are caught, and their code never runs.

## Upgrade notes
- **New findings may appear in `asca-skills`:** the bytecode and oversight rules are on by default. Medium findings don't fail the scan (default `--fail-on high`), so `--telegram change` alerts only if a new high appears.
- **Pre-install gate:** `--gate default` now also blocks `skill.bytecode-mismatch` (exit 3): no legitimate skill ships a cache whose code differs from its source. `--gate strict` adds `skill.bytecode-sourceless`.

**Tests:** 424 passing.
