# asca v0.2.0

The first tagged release of **Agent Supply-Chain Auditor**: a zero-dependency Python toolkit
that audits self-hosted AI agent setups (Hermes, Claude Code, Codex, Cursor, VS Code, Gemini
CLI, goose, Claude Desktop and any MCP client) for supply-chain risk. It sends a Telegram
alert only when something changes.

Same principles as always: Python standard library only, and it **never runs what it scans**
(hooks, git, extensions and packages are read as text). Secrets are never printed.

## What's new

### 🧩 IDE & agent inventory: `asca inventory`
- **What it records:** installed VS Code / Insiders / Cursor / Windsurf / VSCodium extensions
  (and their `-server` remotes), MCP servers, Hermes and Claude Code plugins, OpenClaw
  extensions and skills, each with publisher, version and a content hash.
- **What it alerts on:** changes since the last run.
  - 🟥 known-bad builds, critical. Built in: the tampered `anthropic.claude-code` 2.1.312 and
    2.1.313 that the Cursor marketplace served on 2026-10-29.
  - 🟧 files changed without a version change (tamper), and publisher swaps.
  - 🟨 new items, new publishers, changed MCP launch definitions, marketplace → side-loaded VSIX.
- **First run:** learns silently. Offline; it never calls `code`, `npm` or `git`.
- **Limit:** a malicious build shipped as a *new version* (as the Cursor one was) looks like
  a routine update until it's on the known-bad list. Add your own with `--known-bad`. The
  inventory gives you the record of which version you had and since when.

### 🔀 Agent-config tamper (in `asca`)
Based on Symantec's report on unauthorized Codex / Claude Code relay services. They install
the genuine CLIs, then turn off the sandbox, reroute model traffic, plant a token and disable
telemetry.
- **Rated high:** Codex `danger-full-access` and write-sandbox network access, Claude Code
  `bypassPermissions`, Hermes approvals off.
- **Known relay domains:** critical.
- **Endpoint override + sandbox off / telemetry off / token in config:** high (the relay
  combination).
- **Endpoints:**
  - Local and private-network endpoints (Ollama, LiteLLM on your LAN) are **never flagged**.
  - A company gateway or any other unknown public host is reported **medium**. Accept it in
    your baseline if it's yours.
  - Well-known providers (OpenRouter, …) are listed as info.

### 🐍 Python startup hooks (in `asca`)
Python runs `import` lines in `.pth` files and imports `sitecustomize` / `usercustomize` on
every start, pip included. Both LiteLLM compromises (1.82.8 in March, 1.107.0 in October)
used this.
- **Where it looks:** the Hermes venvs, user site, pipx and uv tools, every virtualenv under
  `--repos`, and system site-packages.
- **Critical:** the known-bad LiteLLM versions and hook files.
- **High:** a hook no installed package owns, or one using exec, base64, subprocess or the
  network.
- **Medium:** a hook installed by a package (the package is named).
- **Standard hooks:** virtualenv, editable installs, the distutils shim and similar stay quiet
  only when name *and* content match.

### 🪝 Repo-supplied agent hooks (in `asca`)
Commands a cloned repo can make your agent or editor run: Claude Code `.claude/settings.json`
hooks, `statusLine` and `apiKeyHelper`, Cursor `.cursor/hooks.json`, and `.vscode/tasks.json`
tasks that run on folder open.
- **Committed vs local:** files committed to the repo (read from `.git/index`, without
  running git) rate higher than your own local settings.
- **High:** commands that fetch or send data.
- **Also checked:** repo settings that redirect the model endpoint, bypass permissions,
  pre-approve every shell command or auto-enable the repo's MCP servers.

### 🔑 GitHub token scopes (in `asca`, opt-in: `--github-token-scopes`)
Finds GitHub tokens agents can reuse (`gh` `hosts.yml`, `GH_TOKEN`/`GITHUB_TOKEN`,
`~/.git-credentials`) and looks up their scopes.
- **High:** `delete_repo`, `admin:org` and other admin scopes.
- **Medium:** `workflow`, `write:packages` and similar.
- **Low:** classic tokens with no expiry, and stored tokens that no longer work.
- **Why it's opt-in:** it sends one HTTPS request per token, only to that token's own GitHub
  host.
- **Limits:**
  - Fine-grained token permissions aren't visible to it.
  - The macOS Keychain / OS keyring isn't read.

### 🍎 macOS setup
`docs/macos.md` plus `scripts/macos/install-launchd.sh` schedule the full audit, the skill
scanner and the inventory as daily launchd jobs, with Telegram alerts on change and a ⚠️ note
if a job errors.

## Also since 0.1.0
- **Secrets in agent session history:** transcripts of Claude Code, Codex, Hermes and Cursor,
  with budgets and redacted output.
- **Stray agent instructions:** `AGENTS.md`, `CLAUDE.md`, `.cursorrules` … in Downloads,
  Desktop or temp folders, where an agent started there would obey them.
- **`asca-skills` per-rule gate:** `--gate` blocks only near-certain signals (exit 3),
  `--quarantine` moves skills aside without deleting them, and `restore` puts them back.

## Upgrade notes
- **New checks are on by default:** agent config, Python startup hooks and repo hooks. Turn
  them off with `--no-agent-config`, `--no-python-startup` and `--no-repo-hooks`. The GitHub
  token check is off unless you pass `--github-token-scopes`.
- **The full audit now reads agent session history.** That's slower: about a minute on a
  busy host. Use `--session-budget-mb` to cap it, or `--no-session-history` to skip it.
- **New findings mean a new alert.** With `--telegram change`, expect one message on your
  first run after upgrading. Review the findings, then accept the ones you intend with
  `--write-baseline` (and edit the file).
- **Requirements:** Python 3.10+. Reading Codex's `config.toml` needs 3.11+; on 3.10 asca
  reports a LOW "not checked" instead.
