# asca v0.4.0

A dashboard page for each host, clearer patch alerts, and a new check for coding agents in GitHub workflows that strangers can start. Same principles as always: Python standard library only, and asca never runs what it scans.

## What's new

### 🤖 Coding agents in GitHub workflows that anyone can trigger
A workflow that runs Claude Code, Gemini CLI, Codex or GitHub's AI action on an issue, a comment or a pull request from a fork hands a stranger's text to an agent that holds the job's token and secrets. In 2026 researchers used this to steal keys through nothing more than issue and PR text ([Comment and Control](https://oddguan.com/blog/comment-and-control-prompt-injection-credential-theft-claude-code-gemini-cli-github-copilot/), [Aikido PromptPwnd](https://www.aikido.dev/blog/promptpwnd-github-actions-ai-agents)). The vendors fixed related flaws in their actions ([GHSA-8q5r-mmjf-575q](https://github.com/anthropics/claude-code-action/security/advisories/GHSA-8q5r-mmjf-575q), [GHSA-wpqr-6v78-jr5g](https://github.com/google-github-actions/run-gemini-cli/security/advisories/GHSA-wpqr-6v78-jr5g)), but the workflow itself decides who can start the agent and what it can reach.
- **New rule `repo.ci-agent-untrusted-trigger`:** asca reads `.github/workflows/*.yml` in every repo it audits. It never runs anything, and it only parses files that use a known agent action or call an agent CLI in a `run:` step.
- **High:** the agent can be steered **and** holds something worth stealing. Steered means the issue or PR text is pasted into its prompt, it runs on the pull request's own code under `pull_request_target` (so it reads the attacker's `CLAUDE.md`, `AGENTS.md` or `.mcp.json`), or claude-code-action's "write access only" check is switched off. Worth stealing means a write token, extra secrets or an OIDC token.
- **Medium:** the same in a read-only job without secrets; claude-code-action's own documented triage setup; pasted text in a job only maintainers can start; or an agent anyone can start that holds a write token or secrets.
- **Low:** an agent anyone can start in a read-only job without secrets. Also new, `repo.ci-agent-unpinned`: an agent action that follows a tag or branch instead of a commit.
- **Real gates count, look-alikes don't:** `author_association` checks, actor allow lists, same-repo-only PRs, permission-check steps and the action's default write check are recognised. Checking the repository name, "commenter is the issue's author" or an `@claude` trigger phrase limits nothing, so those still count as open.
- **Skip it** with `--no-ci-agents`.

### 📊 A dashboard page for each host (`asca dashboard`)
One HTML page with every asca job's status and the fixes to act on, so you don't have to dig through `.md` reports.
- **Job cards** for audit, skills, inventory, fleet and egress, with status, counts and last run. A job with no new report for over 26 hours is marked **STALE** (`--stale-hours`), so a scheduled job that quietly stopped is visible.
- **Act on these:** every critical, high and medium finding with *where*, *why* and *fix*. Findings first seen in the last 36 hours get a **NEW** badge.
- **Fixed recently:** findings that disappeared in the last 7 days. A missing or unreadable report never counts as a fix.
- **Audit trend**, Hermes patch level and the egress summary.
- **Rebuilt automatically** after every job by the macOS runner and `scripts/asca-daily.sh` (`ASCA_DASHBOARD=off` turns it off).
- **Safe by construction:** a file, not a server; no JavaScript and a strict `Content-Security-Policy`; every scanned value HTML-escaped; written with mode `0600`.

### 📍 The dashboard's location at the end of every report
When `ASCA_DASHBOARD` is set, every Markdown report and Telegram alert ends with `Dashboard: <path>`. The runners set it for you. Set it yourself to show a path for another machine, e.g. `myhost:~/.hermes/state/asca/dashboard.html`. Only the path is added, no report content.

### 🟨 Fleet monitor: honest headlines and optional reminders
- **Three headlines instead of two:** "N security fixes behind", "N releases behind (no security fixes)" and "up to date". Before, a host one plain release behind was headlined "patched", which read as "nothing to do".
- **`--remind-days N`** (off by default): while a host stays behind, the alert repeats every N days instead of going quiet until something changes.
- **How long it's been behind:** the headline, the per-instance line and the dashboard's patch card show the day count, e.g. `⏰ Reminder · 🟨 myhost/hermes: 1 release behind for 3 days (v0.23.1 released 10 Nov, no security fixes)`. Days count from the publish date of the oldest release the host is missing, in the security-fix case too. If that date is unknown, the count is left out rather than guessed. A growing count never triggers a `change` alert by itself.

### 🧩 YAML anchors and aliases
asca's built-in YAML reader now understands anchors, aliases and merge keys (`&steps`, `*steps`, `<<:`). Real workflow files use them to share steps between jobs, so the new check sees aliased jobs too.

## Verified
- **False positives (CI-agent check):** 794 real workflow files from the vendors' examples, 18 large agent and tooling repos and 106 repos found by GitHub code search; 188 of them run an agent. Six jobs are rated high, and each was read by hand: they paste stranger text into an agent holding a write token or extra secrets, switch the write check off with extra bot tokens in the job, or both. claude-code-action's own `issue-triage.yml` example comes out medium.
- **YAML reader:** over 2,069 YAML files it now reads 33 more than before and loses none; the 15 whose result changed differ only where an anchor is now resolved.
- **On a real Hermes host:** the daily audit is unchanged by the new check, and the dashboard and report footer have run there daily since 11 November.

## Upgrade notes
- **New findings may appear in the daily audit:** the CI-agent check is on by default. A high finding fails the audit (default `--fail-on high`), so `--telegram change` sends one alert if one of your repos has such a workflow. Medium and low findings don't fail it.
- **Dashboard on macOS:** after `git pull`, the page appears at `~/.local/state/asca/dashboard.html` after the next scheduled run.
- **Fleet reminders are opt-in:** add `--remind-days 3` (or any N) to your fleet job to get them.
- **YAML files that use anchors,** which asca couldn't read before, are now read normally.

## Limits
- The CI-agent check reads workflow files only. It can't see repository or organisation settings (default token permissions, approval for fork PRs, branch rules), reusable workflows in other repos, or composite actions that wrap an agent under another name. A job without a `permissions:` block is reported as unrestricted, because the repository default may be read-write.

**Tests:** 477 passing.
